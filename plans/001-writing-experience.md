# Minc 编辑体验：先保证一篇笔记能连续写完

基于 `903f64b4`（2026-11-23）。四批改动均已实现。自动化覆盖常见编辑操作与长文重排；macOS 的完整连续操作仍须在独占桌面上复测。

## 目标

从空白页开始，输入中文、组织标题和列表、改写几段文字、插入网页内容，保存重开后能接着写。每个动作都应有可预期的光标位置、选区、撤销结果和保存内容。不要求复刻 Typora 的所有行为；以同一份临时笔记对照输入习惯，文件仍采用可移植的 Markdown。

保留 Winc 的文档模型、输入法、文件树、撤销和排版。只提供一个可编辑的排版视图，不增加源码模式、块存储或插件系统。本轮不扩展阅读器、属性类型、图谱和 IDE 功能。

## 为什么先做这几件事

- [现有验收记录](README.md#编辑体验)已经确认中文输入、组合字符、空行、标准硬换行和富文本剪贴板可用。本轮开始前已知粘贴表格后光标可能停在末尾分隔符，原有 `pasting_a_web_table_preserves_cells_even_when_text_is_absent_or_tabular` 只检查源码、撤销和解析结果，没有检查下一次键入落在哪里。
- [`live_caret.rs`](../crates/winc-app/src/app/preview/markdown/live_caret.rs)在拖选时暂时固定展开标记的块；[`live.rs`](../crates/winc-app/src/app/preview/markdown/live.rs)的 `live_format` 只处理单行选区。需要分别验证「跨行选得准」和「对跨行选区执行格式命令」；前者是基本操作，后者需要定义适用范围，不能用同一个测试代替。
- [`markdown.rs`](../crates/winc-app/src/app/preview/markdown.rs)已有按文档 ID 和修订号衔接的前后台解析；`time_large_markdown` 和 `time_huge_blocks` 已能测量部分排版成本，但以旧分栏路径为主要入口。长文的卡顿或跳动先测当前单视图，再判断是解析、排版还是屏幕锚点的问题。

## 顺序与验收

| 顺序 | 任务 | 用户可见的验收 |
| --- | --- | --- |
| 1 · P0 · 已验收 | 连续录入及结构边界：先修表格粘贴的光标，随后查回车、退格、列表退出、代码块后继续写 | 在普通段落或文末粘贴表格后，直接输入进入正文；不会改最后一格。退格不会吞掉无关段落；一次撤销能恢复一次粘贴。 |
| 2 · P0 · 自动化通过 | 光标、选区和输入法 | 鼠标拖选和 `Shift` + 方向键能跨软折行、空行、标题和列表。反向拖选、选区上键入或粘贴、复制及撤销结果正确；组合重音、连写 emoji 和中文候选上屏不丢字、不重字。在前后台解析交替时也验证这些动作。 |
| 3 · P0 · 已采基线 | 长文中的输入与滚动 | 在约 100 KB、1 MB 的混合文档，以及长列表或表格中测首屏、连续输入、拖选和跳到大纲。输入和后台排版交接时不无故把光标移出视口；手动滚动和主动点击大纲不被旧的自动跟随打断。 |
| 4 · P1 · 已实现 | 找得到常用格式，页面有一致的节奏 | 先统一正文行高、段距、标题层级、阅读宽度和中英文混排；用已有选区工具栏与斜杠菜单承接加粗、标题、列表、链接、表格。不支持的跨块操作明确不可用；不再造一套常驻工具栏。 |

第 1、2 批先做操作及回归；第 3 批可并行采基线，优化要等证据。第 4 批先看深浅色、窄宽窗口及中文正文，再定具体间距。以上阶段不依赖 IDE 清理。

### 固定一条桌面验收路线

用 Minc Dev 和临时文件。每次发布候选版本，重复：空白笔记 → 中文 IME 写两段 → 加小标题和任务列表 → 鼠标及键盘跨段选取 → 用网页表格替换一段或插入文末 → 继续写一行 → 撤销、重做 → 保存、重开。记录「操作、预期、实际、保存源码」；排查跳动时补录屏。用 Typora 对照相同输入，不把它的专有格式或换行实现当验收条件。

长文用程序生成的固定内容，同一机器、同一窗口和构建方式采样。分别记录输入到首个可见更新、解析完成、排版与绘制的耗时分布（p50/p95），以及非主动跳转的视口位移；离屏 `paint` 计时只代表应用路径，不代表键盘到屏幕的延迟。先留基线再定预算，不在 CI 写依赖单机速度的绝对毫秒断言。小笔记也跑同一组动作，避免长文优化拖慢日常写作。

## 第一批可执行任务：粘贴表格后能直接继续写

**优先级 P0；工作量 M；风险中。** 粘贴和普通编辑共用选区、撤销与输入法状态。无需先改解析器或另起编辑模型。

### 现状与范围

- `crates/winc-app/src/app/editor/paste.rs`：`paste_into_editor` 先处理文件，再处理选区网址、HTML、纯文本、图片。HTML 转换结果目前直接 `run(Command::Insert(markdown))`。
- `crates/winc-app/src/app/editor/editing.rs`：`paste_text` 是纯文本入口，也调用 `markdown_paste`。不改变普通纯文本或「粘贴纯文本」的语义。
- `crates/winc-app/src/app/preview/markdown/paste.rs`：`Spot::block` 用粘贴点前后文字决定空行，并去掉转换文本的尾换行；`markdown_html_paste` 与 `markdown_paste` 负责 HTML / TSV 转换。不要把以 `|` 开头的普通段落当表格，也不要强制所有 HTML 块改变光标位置。
- `crates/winc-app/src/app/preview/markdown/live.rs`：`live_append_paragraph` 已定义在文末离开结构块的常规行为；供参考，不直接在表格粘贴后再触发一条插入命令，否则可能多耗一次撤销。
- `crates/winc-app/src/app/snapshot/preview/markdown.rs`：扩展现有网页表格粘贴测试，用 `snapshot/preview.rs` 的 `live_doc`、`put_caret`、`after_caret`、`settle` 等助手。测试笔记全部在临时目录生成。

允许修改上述五个实现／测试文件及必要时 `crates/winc-app/src/app/preview/markdown/{laid,live_caret}.rs`（仅表格粘贴的光标落点）。不要改 `winc-editor` 的撤销协议、全局粘贴顺序、解析版本策略、表格普通键位或笔记磁盘格式。检查漂移：`git diff --stat 903f64b4..HEAD -- crates/winc-app/src/app/editor/{paste,editing}.rs crates/winc-app/src/app/preview/markdown/{paste,live,laid,live_caret}.rs crates/winc-app/src/app/snapshot/preview/markdown.rs`；若已有相关修复，先用下面的测试确认，不叠加第二套逻辑。

### 步骤

1. **先锁定故障。** 扩展现有测试，保留 HTML-only、HTML+TSV 两种剪贴板输入，再加空文档和文末。断言光标不在表格单元格内、下一次直接键入落在正文，而非仅断言文档里存在 `Block::Table`。中间插入的测试继续检查 `前`、`后` 和单元格原文不变。至少做一次不经过 `settle` 就立即键入的路径，另一次检查排版收敛后的落点。若自动化没有复现旧问题，先复跑桌面路线并记录差异；不要凭猜测调整全局标记显示。
   - 验证：`cargo test --locked -q -p winc-app --lib pasting_a_web_table`；修复前记录落点或后续键入的实际失败。
2. **只调整实际生成的表格。** 让结构化粘贴路径在一次编辑内确定插入内容与结束落点。若后面已有正文，落在该正文开头，不改变正文已有内容；若表格是文末最后一个块，落在紧随表格的可编辑正文行。仅在确有需要时随同一笔编辑补 Markdown 的块边界，已有边界不重复补。保留 HTML 优先级、单元格内容、链接套选区、代码内字面粘贴与 CRLF 行尾规则；命中粘贴成表格的 TSV 应走相同落点约定。
   - 验证：同一组测试通过。对刚完成粘贴的文档做一次撤销，恢复粘贴前源码和选区；重做恢复表格和可继续输入的位置。保存重开仍识别表格，下一次键入生成独立正文。
3. **走回归。** 补一个负例：普通含 `|` 的行或代码块内粘贴不移动光标到段外。跑排版和编辑回归，再用临时笔记做桌面验收，观察粘贴后的第一帧和紧接着输入中文的结果。
   - 验证：`cargo fmt --all --check`、`git diff --check`、`cargo test --locked -q -p winc-app --lib app::snapshot::preview::markdown`、`cargo test --locked -q -p winc-app --lib app::snapshot::preview::live`、`cargo test --locked -q -p winc-preview --lib markdown::enter` 都通过。规划时，现有网页表格测试、26 项实时编辑测试和 10 项换行测试已通过；新增落点断言尚未运行。

### 完成条件与停止条件

- [x] HTML-only、HTML+TSV 以及实际转换成表格的纯 TSV，都能在表格之后接着写；中间插入和文末均通过。
- [x] 一次撤销恢复原内容与选区，重做后仍能接着写；保存重开符合标准 Markdown，原有正文和单元格内容未被误改。
- [x] 增加无等待绘制的落点断言；在 macOS 临时笔记中实测 `⌘V` 后直接输入拼音上屏，以及等到自动保存后再输入，保存文件都保持表格不变，汉字写在下方正文；用相同剪贴板对照时，Typora 把后续输入留在最后一格。
- [x] 普通粘贴、链接、代码与 CRLF 的回归通过。修复前立即键入得到 `| 茶 | 甲 |继续`；修复后表格与 `继续` 之间有标准段落边界。

若需要改变 Winc 的通用撤销语义，或只能靠重写源位置映射消除闪烁，先保留复现，单独提交设计判断。执行时以可回退的小提交组织，提交说明用 `fix: ...` / `test: ...`，未经授权不推送。未来若新增图片或多块粘贴，应各自明确落点，避免把表格规则套到所有结构化内容。

### 结构边界验收记录

- 新回归在 CRLF 笔记中从空任务项退出、连写两段、合并并撤销；已完成的任务和行尾风格不变。
- 代码块退出和正文退格使用相同的围栏判定。较短的内围栏、尾随代码的记号不算闭合；长围栏、波浪号、引用里的代码块照常工作。代码行里的字面 `>` 不当成空行处理。
- Minc Dev 用临时笔记实测：在四枚反引号包裹、正文内含三枚反引号的代码块上按 `⌘↩`，用拼音输入并保存，汉字落在代码块下方，源围栏未动。

### 跨行选区验收记录

- 复现：从 `**甲乙**` 的「乙」拖到下一段标题，普通复制曾得到 `乙**`，因为它只解析截断后的源码。现在使用选区端点的段落解析上下文，裁掉未选文字；正反方向复制结果一致，HTML 保留可用的样式，也沿用既有链接过滤。明确「复制为 Markdown」的入口未改。
- 回归覆盖 `Shift` 加方向键跨空行或软折行、选区粘贴、替换后的撤销，以及连续三次上屏不等待排版。使用中文、组合重音、连写 emoji 验证保存内容与选区。macOS 临时笔记实测了键盘跨行选择、单键替换、一次撤销并核对磁盘内容。
- 跨段改写：中文上屏替换反向选区，保留未选中的简单粗体；撤销恢复 CRLF 原文及原选区方向，重做复现替换。简单斜体和删除线也适用；嵌套样式、链接以及行内代码不猜测补标记。
- 后台交接：同一修订内位置未变、仍在视口的光标从旧排版交给新排版时保持在原处；测试允许 2 逻辑像素的误差。旧结果尚未应用时发送连续中文、emoji 和组合重音上屏，并断言新排版不覆盖文本、不移动选区，也不会把已主动滚开的页面拉回。另测了旧解析尚未交接时点大纲跳到第 900 节，随后手动滚动并反向拖选。

### 单视图长文基线

`cargo test --locked -q -p winc-app --lib time_single_view_writing -- --ignored --nocapture` 生成四种样本。下表是同一台 macOS 开发机上测试构建的单次运行，每项 16 个样本，单位毫秒（p50 / p95）。首帧包括一次输入与绘制；交接绘制从收到新解析结果起计。滚动每次移动 120 逻辑像素，远跳直接跳转到不同文档位置。它们不包含系统合成和显示器延迟。

| 样本 | 输入首帧 | 解析 | 交接绘制 | 连续滚动 | 远跳 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 混合 105 KiB | 12 / 13 | 17 / 18 | 12 / 13 | 5 / 11 | 12 / 13 |
| 混合 1,072 KiB | 91 / 94 | 178 / 184 | 87 / 107 | 33 / 91 | 91 / 130 |
| 列表 135 KiB | 3 / 5 | 17 / 29 | 3 / 5 | 2 / 3 | 2 / 3 |
| 表格 91 KiB | 25 / 58 | 17 / 26 | 99 / 119 | 3 / 4 | 3 / 4 |

采样发现，长文重排会为每段之间的空行重复从 Rope 查找字节位置。现在解析时生成一份共享的空行字节索引，重排只更新几何位置。同一版计时脚本比较，1,072 KiB 远跳中位数约从 243 ms 降到 91 ms。大混合文档首帧和大表格交接仍可能感觉到停顿；这是一份可复跑的基线，不是流畅度承诺。宽度改变时保留视口顶部的块，使用新视口高度限制滚动范围。

### 页面与格式入口

- 正文「标准」宽度上限 720 逻辑像素，「较宽」为 1040。只有一级标题带横线；保留正文 1.5 倍行高和现有段距，使可编辑空行与普通段落的转换不推挤后文。`shoot_writing_page` 生成浅色宽窗和深色窄窗样图。
- 行内格式命令限单行正文选区；表格内快捷键限单元格。跨段选区、代码块或工具栏会超出视口时不弹出浮动工具栏。斜杠命令消去查询并插入结构算作一次编辑，可整步撤销、重做。
- 本轮在隔离的 Minc Dev 窗口用拼音从空白笔记写入「你好」「文章」两段，并核对保存文件。完整组合路线（同一次会话的格式、拖选、网页表格、撤销重做和重开）及长文桌面滚动尚未复测完成；各操作的自动化结果与已有桌面单项记录分开保留。
- 最终离屏检查：应用预览 162 项、Markdown 解析与预览 189 项、排版 21 项通过。应用预览并发运行时有一次离线阅读图片断言失败，单项和整套单线程重跑通过；本轮未改阅读器。
