# 可观测性与测试指标蓝图

本文档描述 Minc 的可观测性与测试指标体系：衡量什么、如何衡量、以什么样本衡量，以及指标在开发流程中的作用。具体的预算数值与实现方式在实施时另行确定，不在本文档范围内。

---

## 1. 目的

- 让性能与正确性**可度量**：每一项关键体验都有对应的指标，而不是依赖主观感受。
- 让退化**可发现**：任何改动造成的性能下降或行为回归，都能在合入之前被识别。
- 让问题**可定位**：当指标异常时，能够判断耗时或错误发生在哪个环节。
- 让决策**有依据**：架构取舍与优化方向以数据为基础。

---

## 2. 原则

### 2.1 本地优先，不采集用户数据

可观测能力服务于开发与诊断，默认只在本地运行，不向任何外部服务上报。用户可在需要时主动导出诊断信息，导出内容不包含文档正文。

### 2.2 测量不影响被测对象

测量机制在关闭时不产生额外开销；开启时，测得的耗时与正常运行一致。

### 2.3 可复现

指标基于固定的样本、固定的操作序列与确定的输入产生。同一构建、同一环境下的重复测量结果应保持稳定。

### 2.4 贴近真实

样本与操作序列反映真实的写作与阅读场景。合成样本用于检验规模与极限，真实场景样本用于检验实际体验，两者缺一不可。

### 2.5 分级使用

指标分为两类：

- **门禁指标**：有明确预算，超出即视为退化，阻止合入。
- **参考指标**：只记录与展示，用于观察趋势和辅助分析；在测量方法稳定、波动可控之后，可升级为门禁指标。

### 2.6 可追踪

指标结果按构建记录并可横向比较，使长期的缓慢退化同样能够被发现。

---

## 3. 指标体系

指标分为三个维度：**性能指标**衡量快不快、省不省；**正确性指标**衡量对不对、全不全；**运行期观测指标**用于在问题发生时定位原因。

### 3.1 性能指标

#### 应用整体

| 指标 | 衡量内容 |
|---|---|
| 启动耗时 | 从启动进程到呈现文档首帧的时间 |
| 空载内存 | 打开文档后静置时的物理内存占用 |
| 滚动帧耗时 | 连续滚动期间单帧耗时的分布 |
| 按键到出帧耗时 | 一次按键从处理到画面更新的时间分布 |
| 滚轮跟随 | 快速滚动时画面落后于输入的程度与停止后的到位时间 |

#### Markdown 编辑与预览

| 指标 | 衡量内容 |
|---|---|
| 解析耗时 | 全文解析与局部解析各自所需的时间，及其随文档规模的变化 |
| 首屏耗时 | 从切换到预览到首屏内容完整呈现的时间 |
| 排版耗时 | 首次排版、增量排版与整体重排（宽度、字号变化）各自的耗时 |
| 编辑出帧耗时 | 在可编辑预览中键入、删除、换行时从按键到画面更新的时间 |
| 光标移动出帧耗时 | 在可编辑预览中移动光标、扩展选区时的出帧时间 |
| 预览滚动帧耗时 | 预览中连续滚动的单帧耗时分布 |
| 复杂内容耗时 | 公式、图表、表格、图片等内容的排版与解码耗时 |
| 长文档内存 | 打开、滚动并编辑长文档后的内存占用及其随规模的增长趋势 |

#### AI 协作

| 指标 | 衡量内容 |
|---|---|
| 首字延迟 | 从发送请求到第一段内容呈现的时间 |
| 流式更新开销 | 流式输出期间每次更新的绘制耗时 |
| 空闲开销 | 未使用 AI 功能时的进程与内存占用 |

### 3.2 正确性指标

| 指标 | 衡量内容 |
|---|---|
| 解析回归通过率 | 解析回归语料中各条用例的通过情况 |
| 格式覆盖率 | 真实场景文档中所有已支持的语法均被正确解析与呈现，无未识别内容 |
| 渲染一致性 | 关键文档在固定尺寸与主题下的渲染结果与基准一致 |
| 编辑语义通过率 | 结构化编辑、标记显隐、选区与剪贴板、输入法等用例的通过情况 |
| 往返一致性 | 打开后不做修改直接保存不产生任何文本差异；复制与粘贴在各格式之间转换后语义不变 |
| 位置正确性 | 多语言文字、组合字符与不同换行风格下的位置换算与光标行为正确 |

### 3.3 运行期观测指标

运行期观测用于开发与诊断，帮助定位性能问题与异常行为。

| 指标 | 衡量内容 |
|---|---|
| 帧耗时分解 | 单帧中解析、排版、绘制、呈现各阶段的耗时 |
| 慢帧记录 | 超出帧预算的帧及其主要耗时阶段 |
| 后台任务状态 | 解析、图片加载、文件读取等后台任务的排队与完成情况 |
| 缓存效率 | 排版缓存、画面复用等缓存的命中情况与占用规模 |
| 内存构成 | 文本、排版结果、图片、字形等各部分的内存占用 |
| AI 请求状态 | 请求延迟、失败率与失败原因分类 |

## 4. 测试样本体系

样本是指标的基础。样本体系由四类样本构成，各自承担不同的检验目的。

| 类别 | 目的 | 特征 |
|---|---|---|
| **真实场景样本** | 检验实际写作与阅读体验，以及格式覆盖的完整性 | 真实领域的完整文章，内容准确，结构自然，覆盖全部已支持的语法 |
| **规模样本** | 检验性能随文档规模的变化 | 自动生成，规模可调，内容确定 |
| **回归语料** | 锁定已知的易错写法与已修复的缺陷 | 最小化用例，每条只验证一个行为 |
| **极端样本** | 检验边界条件下的稳定性 | 超长段落、超大表格、深层嵌套、大量图片、复杂公式等 |

真实场景样本存放于 `testdata/markdown/`，首篇为流行病学领域的《传染病动力学入门：SIR 模型、基本再生数与群体免疫》。

## 5. 现状与差距

### 已具备

- 基准工具已覆盖启动耗时、空载内存、滚动帧耗时、按键出帧耗时与预览滚动帧耗时，并对照预算判定。
- 已有可编辑预览中键入与光标移动的出帧测量，以及滚轮跟随、大文件查找等参考指标。
- 已有解析回归语料、离屏渲染测试与截图工具。

### 待补齐

- Markdown 编辑相关的出帧指标目前仅供参考，尚未设立预算。
- 缺少解析、排版、绘制分阶段的耗时度量，性能问题难以快速定位。
- 缺少基于真实场景文档的格式覆盖校验与渲染一致性校验。
- 缺少长文档在编辑过程中的内存增长度量。
- 缺少面向开发与诊断的运行期观测能力。
- 指标结果尚未按构建记录，无法观察长期趋势。

---

## 6. 演进方向

1. **样本完善**：建立真实场景样本与极端样本，使样本体系覆盖全部四类。
2. **正确性校验**：基于真实场景样本建立格式覆盖校验与渲染一致性校验，纳入常规测试。
3. **性能指标细化**：引入分阶段耗时度量，补齐 Markdown 相关的性能指标，并将稳定的参考指标升级为门禁指标。
4. **运行期观测**：在开发构建中提供帧耗时分解、慢帧记录与内存构成等诊断能力。
5. **趋势追踪**：按构建记录指标结果，支持跨版本比较与退化告警。

---

## 7. 约束与关注点

- **隐私**：任何观测能力不得默认上报数据，诊断导出不得包含文档内容。
- **零开销**：测量与观测代码在关闭时不得影响性能。
- **环境一致**：预算基于明确的硬件与系统环境标定，环境变化后须重新标定。
- **结果稳定**：门禁指标须具备足够的稳定性，避免因测量波动造成误判。
- **样本真实**：真实场景样本须保持内容准确，不以构造的无意义文本代替。
- **持续维护**：新增功能须同步补充对应的指标与样本，缺陷修复须附带回归用例。
